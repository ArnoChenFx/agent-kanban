Quick start

Install, create a board, start the server. Three steps.

# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/ArnoChenFx/agent-kanban/main/install/install.sh | bash

# Windows, any shell including cmd
powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/ArnoChenFx/agent-kanban/main/install/install.ps1 | iex"

# in your repository
agent-kanban init
agent-kanban install-protocol
agent-kanban serve               # → http://127.0.0.1:7788/

Put your agents on the board

Three complementary options: the protocol file enforces the habit, the MCP tools do the operations, the skill teaches the workflow.

The protocol file (works with any agent)

Writes a managed block between agent-kanban:begin and agent-kanban:end markers, and touches nothing else in the file. doctor reports when the installed block is behind the CLI version.

agent-kanban install-protocol        # write the managed block into AGENTS.md
agent-kanban install-protocol --check   # CI guard: exits 2 if missing or outdated
agent-kanban install-protocol --file .cursor/rules/kanban.mdc

MCP tools

Register the server with any MCP-capable harness. The board is found by walking up from the harness working directory, so agents in the same repository share it automatically.

claude mcp add agent-kanban -- agent-kanban mcp
pi mcp add agent-kanban -- agent-kanban mcp
20 tools over stdio, thin wrappers over the same core the CLI uses. Every tool returns { ok, data, next_actions }, failures carry the same exit-code semantics as the CLI.

The agent skill

Ships the parts an agent keeps getting wrong as reference files: the full command reference, the MCP tool mapping, the local-versus-remote differences, and a troubleshooting table keyed by exit code. Install it into a project that already has a board.

npx skills add ArnoChenFx/agent-kanban --skill agent-kanban

Server on one machine, CLI everywhere else

One serve process can host many projects. Each project is fully isolated: its own tasks, its own tokens, its own ID space. Clients only need the server URL, a project key and a token — no database, no runtime.

On the server machine

agent-kanban serve                                  # prints the admin token once
agent-kanban admin project add my-app
agent-kanban admin token create --project my-app --name "CI runner"
# → k_a1b2c3...

Or with Docker

The compose file pulls the published image from GitHub Container Registry and keeps data in a named volume. The image runs the TypeScript sources on Bun directly, so there is no build step.

cp .env.example .env
# set KANBAN_ADMIN_TOKEN (generate one: openssl rand -hex 16)
docker compose up -d

# or without compose
docker run -d --name agent-kanban -p 7788:7788 -v kanban-data:/data ghcr.io/arnochenfx/agent-kanban:latest
KANBAN_BIND (default 127.0.0.1) and KANBAN_PORT decide how far the server is reachable and which host port it uses. Leave KANBAN_ADMIN_TOKEN empty and the server generates one on first boot, prints it once and stores it in /data/.kanban/config.toml. The container only runs serve — create projects and issue tokens on the /admin page with the admin token.

On a client machine

# write <project>/.kanban/config.toml
mode = "remote"

[server]
url   = "https://kanban.example.com"
token = "k_a1b2c3..."

[project]
key = "my-app"
agent-kanban config show     # confirm what resolved and where it came from
agent-kanban task list       # no flags needed from here on

Or set it up in one command:

agent-kanban config init --server https://kanban.example.com --project my-app --key k_a1b2c3
Mode defaults to remote when a server is set, local otherwise. Precedence: CLI flags > environment variables > config.toml > derived defaults. An empty environment variable counts as unset, not as an empty value.
serve does not terminate TLS and binds 127.0.0.1 by default. Put it behind a TLS terminator before binding 0.0.0.0 — without TLS, tokens travel in plaintext.

Command reference

Run agent-kanban <command> --help for the full option list.

CommandPurpose
agent-kanban initCreate the local board (.kanban/)
agent-kanban install-protocolWrite the agent collaboration protocol into the project's AGENTS.md
agent-kanban mcpRun the MCP server (stdio) so an agent can call the board as tools
agent-kanban session start | end | list | heartbeatSession lifecycle
agent-kanban task add | list | show | claim | progress | block | done | …Task operations
agent-kanban boardSwimlane view in the terminal
agent-kanban contextRead the situation: board + handoffs + suggested actions
agent-kanban resume <task>Take over a task; injects handoff and timeline
agent-kanban handoffWrite a handoff (summary / next / blockers / open)
agent-kanban plan save | show | list | history | at | attachVersioned plans
agent-kanban rebuild [--write]Replay the event log and verify the projection
agent-kanban doctor [--deep]Consistency self-check and repair
agent-kanban export [--out <dir>]Export the event journal (one file per day)
agent-kanban import <dir> [--dry-run]Rebuild the database from a journal (cross-machine migration)
agent-kanban snapshotWrite a human-readable board snapshot
agent-kanban compact [--keep-days 30]Trim old events (snapshots first)
agent-kanban config show | init | set | use | pathConfiguration
agent-kanban project listQuery projects (local database)
agent-kanban admin project … | token …Project and token management
agent-kanban update [--check]Self-update the binary from GitHub Releases (checksum-verified)
agent-kanban serveRun the HTTP + SSE server

Exit codes

A published contract. Agents branch on the code, never on message text.

CodeNameMeaningWhat to do
0OKSuccess—
1USAGEBad argumentsRead details.usage and fix the command
2STATETask missing, illegal transition, missing required --reasonDo not retry as-is
3CONFLICTTask is held by another session with a live leaseWork on something else, or wait. Do not reach for --force
4BUSYDatabase is lockedBack off and retry, at most 3 times
5NOT_INITNo .kanban/ directory, or schema needs migratingRun agent-kanban init
6INTERNALBugReport it, do not retry
7AUTHMissing key, wrong key, or project not foundFix your credentials

More (FAQ, configuration, remote mode, HTTP API) lives in the GitHub README and the developer docs.
