# 一键安装脚本实施笔记（2026-09-27）

## 做了什么

新增 `install/install.sh`（macOS/Linux）与 `install/install.ps1`（Windows），随 Release 一起发布。
用户一行命令即可完成「识别平台 → 下载 → 装到用户级目录 → 加 PATH」。

两个脚本的接口（四个环境变量覆盖项）：

| 变量 | 作用 |
| --- | --- |
| `AGENT_KANBAN_DOWNLOAD_BASE` | 下载根地址，指向本地假 server 就能离线测 |
| `AGENT_KANBAN_VERSION` | pin 版本，改用 `releases/download/v<版本>` |
| `AGENT_KANBAN_INSTALL_DIR` | 换安装目录 |
| `AGENT_KANBAN_SKIP_PATH` | 跳过 PATH 写入（门禁专用，见下） |

## 决策与理由

- **装用户级目录**（`~/.local/bin` / `%LOCALAPPDATA%\Programs\agent-kanban`）。
  整个价值就是"不需要管理员"。脚本里任何时候都不该出现 `sudo`——真出现了，
  `verify-install.ts` 会红。Windows 侧同理，不碰 HKLM。
- **不做 SHA-256 校验**。Release 已有 `.sha256` 可供手动核对，脚本按用户选择走简洁路线。
- **脚本不进 `release-assets/`**。release job 的 `Collect assets` 步骤断言
  `release-assets/` 里非 `.sha256` 的文件数 == 平台数（4），把脚本拷进去会变成
  "expected 4, found 6"。所以 `files:` 里直接写 `install/install.sh`（release job
  已经 checkout 过，工作区里现成）。`verify-workflows.ts` 有一条专门守这个目录约定。
- **不发布 Linux arm64 二进制**（沿用既有决定）。install.sh 在 arm64 上**显式报错并指向
  Docker**，而不是退回 x64：在 Apple Silicon 上装一个跑不了的 x86 二进制，用户会先撞上
  Rosetta、再撞上一条与架构毫无关系的报错，极难自查。

## 踩到的坑

### `spawnSync` + 进程内 `Bun.serve` = 死锁

`verify-install.ts` 原本用 `spawnSync` 跑安装脚本，假 Releases 就跑在**同一个进程**里。
`spawnSync` 同步阻塞事件循环，子进程发过来的 HTTP 请求没人应答，双方互等到超时——
第一次跑就是直接卡死（跑满 60s 被 `timeout` 杀掉，Bun 1.4.2 实测）。

改用异步 `spawn` 后正常。**门禁里凡是要"子进程请求本进程起的 server"，一律不能同步等。**

### 假资产必须是**真二进制**

第一版假 server 返回文本，于是 Windows 上 `& $target --version` 报
`The specified executable is not a valid application for this OS platform`。
改成 shell 脚本也不行：`chmod 0755` 只对二进制文件生效，macOS/Linux 会 Permission denied。
也就是说文本方案在**任何**平台都验不到"装完即用"这条断言。

现在用 `bun build --compile` 现编一个两行的 stub 当假资产（~0.2s）。
顺带两个 Windows 专属的坑：

- `bun build --outfile stub.bin` 在 Windows 上实际写出的是 **stub.bin.exe**，写死名字就 ENOENT。
- `bun build -` 不认 stdin（`ModuleNotFound resolving "-"`），必须先落一个源文件。

### `AGENT_KANBAN_SKIP_PATH` 为什么必须存在

门禁用的是一次性临时目录。如果不加这个开关，`install.sh` 会往开发者自己的 `~/.bashrc`
追加一行指向**已删除目录**的 PATH——CI 跑一次，本机就多一条坏 PATH。
`install.ps1` 同理会写 HKCU 的用户 PATH。

这类"测试对真实环境有副作用"的开关，比事后手工清理可靠得多。

## 验证

```bash
bun run verify:install    # 45 项：静态 + 端到端真装
bun run verify:workflows  # release.yml 的 files/ 与 notes 断言
bun run verify:all
```

已登记进 `.github/workflows/ci.yml` 的 `test` job——那里是三平台矩阵，
`install.sh` 与 `install.ps1` 各自会在真正对应的平台上被跑到。

**发布前本机验不到的部分**：真实 GitHub Release 下载、macOS Gatekeeper/quarantine 行为、
Apple Silicon 上 `uname -m` 的真实取值。这些要等 push tag 后的真实安装。
