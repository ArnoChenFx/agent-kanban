# 2026-02-19 Web 任务详情打不开：前后端形状漂移

## 现象

Web 看板点开任意任务，右侧抽屉报：

```
Cannot read properties of undefined (reading 'plan_id')
```

## 定位

`web/src/lib/api.ts` 的 `fetchTaskDetail` 这样拆服务端返回值：

```ts
const { data } = await executeOp<{ task: Record<string, unknown> }>(...)
const task = data.task          // ← undefined
...
task.plan_id                     // ← TypeError
```

但 `src/core/ops.ts` 的 `task.get` 返回的是**任务本体**（扁平对象），不是 `{ task: ... }` 包装：

```ts
const data = { ...taskToJson(task), body, checklist, dependencies, unfinished_dependencies }
```

CLI（`src/commands/task.ts` 的 `const task = data as Record<string, unknown>`）
与 MCP（`kanban_task_get`）一直按这个形状消费——**只有前端按包装形状取值**。
也就是说这不是服务端改坏了，而是前端从一开始就没对齐契约，且没人发现：
详情页只要 `plan_id` 为 null 以外的情况就会崩，而 `handoff`/`plan` 两条支线又是 `.catch(() => …)` 静默兜底。

探针（临时脚本，直接调 core）确认：

```
=== task.get OK ===  keys: id, project, title, ..., plan_id, ..., timeline
```

## 修复

1. **前端对齐契约**：`fetchTaskDetail` 按“data 即任务本体”取值，并在形状不符时抛可读错误
   （`服务端返回的任务详情形状异常` + 实际字段列表），而不是顺着 `task.plan_id` 崩成 TypeError。
   顺带优化：`timeline: true` 时服务端已在同一响应里附带事件，省掉一次 `events.tail` 往返（保留兜底）。

2. **补两个前端在调、服务端根本没实现的 Op**（同一轮排查发现，症状都是“静默失效”）：

   | Op | 症状 | 修法 |
   |---|---|---|
   | `handoff.list` | 详情页「交接」页签永远显示“还没有交接记录” | 新增 Op，基于 `taskHandoffs()`，返回 `RecoveryContext.pending_handoffs` 同构字段 + `consumed_by`/`consumed_at` |
   | `task.transition` | 看板改状态（拖到别的泳道/菜单切状态）报“未实现的操作” | 新增 Op，复用 `doTransition()`，合法性与守卫（`requireReason` / `requireProgress100` / `forceOnly`）仍由 `transition()` 统一把关 |

   两者都走 `executeOp` 的穷尽性检查：只加进 `Op` 联合类型而不写 `case` 会被 TS 挡住。

3. **补三层回归**（这类漂移的教训是“没人测那条边界”）：

   - `test/web-contract.test.ts`：`task.get` 返回形状、三个页签的数据源 Op、以及两条静态守卫
     （前端源码不得出现 `data.task`；前端调的每个 Op 都必须在 `ops.ts` 里有 `case`）
   - `scripts/verify-web.ts` 新增 §4.1：对真 server 打 `task.get` / `handoff.list` / `task.transition`
   - `scripts/verify-web-ui.ts`（新增，已进 `verify:all`）：无头 Chrome 经 CDP **真点一次卡片**，
     断言抽屉打开、三个页签有内容、无 `plan_id` 异常

   第三层是必需的：前两层都只证明 HTTP 契约，**证明不了 React 渲染时会不会抛**。

## 踩坑记录

- **Radix Tabs 的 tab 在 `mousedown` 上切换**，只派发 `el.click()` 切不动，
  会误判成“页签没数据”。CDP 里要补全 `pointerdown → mousedown → pointerup → mouseup → click`。
- `plan save` **默认就挂到任务上**，要“不挂”才加 `--no-attach`（我一开始写了 `--attach` 直接 USAGE 报错）。
- `bun run --cwd web typecheck`（即 `tsc -b --noEmit`）在本机 PowerShell 下会返回 exit 1 且不打印任何诊断；
  直接 `bun x tsc -b --noEmit` 才看得到真实结果（exit 0）。怀疑是 bun run 的参数透传问题，暂未深究。

## 附：同一轮修掉的排版问题（用户截图反馈）

报障现象两处，都在 `web/src/components/`：

| 现象 | 根因 | 修法 |
|---|---|---|
| 详情抽屉的进度条左右顶到抽屉边框、上下无空隙 | `<Progress>` 写在 `SheetHeader` 的**同级**。`SheetContent` 本身没有内边距（`p-4` 在 SheetHeader/Footer 上），所以同级元素就是贴边 | 进度条移进 `SheetHeader` 内（跟在描述后面），`h-1.5`→`h-1`，并注入状态色 `--chip-color`（与卡片一致） |
| 卡片任务号 `T-0025` 与右上角操作按钮重叠 | 操作按钮是 `absolute top-1.5 right-1 size-6`（hover 浮现），任务号徽标也在右上角同一格 | 任务号挪到卡片**底部元信息行**（与“刚刚”同行），顶部行加 `pr-6` 给按钮留位 |

顺手：拖拽把手原来也用 `MoreHorizontalIcon`（`⋯`），和右上角菜单按钮**同图标**，
换成 `GripVerticalIcon`（抓手）以免误点。

两者都做成了**几何断言**进 `scripts/verify-web-ui.ts`（`getBoundingClientRect` 相交判定），
而不是靠看截图——截图只能证明“我这次看着对了”，几何断言能挡住下次回归：

```
✓ 任务号与操作按钮不重叠  重叠 0 张
✓ 标题不被操作按钮压住  被压 0 张
✓ 进度条左右有内缩（>=12px，不顶抽屉边框）  16px
✓ 进度条与描述有空隙（>=4px）  8px
✓ 进度条与页签有空隙（>=8px）  32px
```

对照截图：`docs/note/images/05b-card-hover-zoom.png`（hover 态卡片）、
`06-task-detail-dark.png`（详情抽屉）。

顺带记一笔：`bun run web:build` 会把入库的 `src/server/assets.generated.ts`
覆盖成真实清单（内含 `web/dist` 字面量路径），此时 `verify:deploy` 的
“空表占位”检查会红。跑完构建想恢复干净状态，重跑一次 `gen:assets` 即可。

顺带修掉的第三处（用户截图反馈）：**卡片操作菜单太窄、文字折行**。

根因在组件层：`DropdownMenuContent` 的类名是
`w-(--radix-dropdown-menu-trigger-width)`，即**菜单宽度 = 触发按钮宽度**。
卡片上的触发器是 `size-6`（24px）的图标按钮，所以菜单实际只有 `min-w-32`（128px），
“释放（保留进度）” 被断成两行。

改法（改组件层而不是改调用点，全项目只有卡片这个菜单用它）：
- `w-(--radix-dropdown-menu-trigger-width)` → `w-fit`（宽度跟随内容）
  并补 `max-w-(--radix-dropdown-menu-content-available-width)` 防止贴边时超出视口
- `DropdownMenuItem` 加 `whitespace-nowrap`
- task-card 的菜单显式 `min-w-40`（160px）

同样做成了几何断言（单行菜单项高 ≈30px，>36px 判为折行）：

```
✓ 菜单已打开  10 项
✓ 菜单宽度不是被触发器压窄的  160px
✓ 菜单项无折行
```

### Radix 组件在 CDP 里的两个坑（同一类问题的两次）

Radix 的交互组件**都不监听 `click`**，而是监听 `pointerdown` / `mousedown`：

- `Tabs`：只派发 `el.click()` → 页签切不动，看起来像“数据没加载出来”
- `DropdownMenuTrigger`：只派发 `el.click()` → 菜单根本不开

写 CDP 脚本时要补全 `pointerdown → mousedown → pointerup → mouseup → click`。
另外 Radix Dialog（Sheet）打开时会锁焦点，看板上的点击全部失效，
所以测看板交互前要先关抽屉。

## 结论（写给下一个人）

`web/` 不在根 `tsc --noEmit` 的编译范围里，也没有前端测试运行器，
所以“前端按什么形状拆返回值”这件事**没有任何机器在检查**。
现在有三条线兜着了：静态守卫（`data.task` / Op 存在性）、HTTP 契约（`verify:web`）、
真浏览器点击（`verify:web:ui`）。改 `task.get` 返回形状前，先看
`docs/plan/002-接口契约.md` §4.0.2 —— 那里写了要一起改的三处。
