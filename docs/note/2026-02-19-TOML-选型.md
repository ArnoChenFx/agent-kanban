# TOML 选型记录：不要手写，用 Bun 内置

日期：2026-02-19（实现 `.kanban/config.toml` 时）

## 背景

要给 agent-kanban 加项目级配置文件 `.kanban/config.toml`。我先写了 `src/core/toml.ts`
——一个约 200 行的手写 TOML 子集解析器（支持注释、字符串、数字、布尔、单行/多行数组、表头），
理由是"agent 环境可能无法联网装依赖"。

## 转折

写完后意识到应该先查一下 Bun 本身有没有内置能力（用户也提醒了这一点）。
探针验证（Bun 1.4.2 / Windows）：

```ts
Bun.TOML.parse      // function，同步
Bun.TOML.stringify  // function
await import("./config.toml")  // 也能当模块导入
```

结论：**Bun 1.2+ 已内置完整 TOML 支持**，我手写的 200 行子集解析器是多余且更差的
（不支持多行字符串 `"""..."""`、数组表 `[[x]]`、日期时间）。

## 内置能力的实测细节

| 行为 | 结果 |
| --- | --- |
| `Bun.TOML.parse` 同步性 | 同步，可直接吃 `readFileSync` 的结果 |
| `stringify` 字段顺序 | 标量在前、表在后（符合人读习惯） |
| 注释 | 不保留（TOML 规范本身也不支持） |
| 嵌套表 `[a.b]` | 支持，解析为 `{a:{b:{...}}}` |
| 多行数组 | 支持 |
| 数组表 `[[x]]` | 支持 |
| Windows 路径 | `'C:\Users\x'` 单引号形式可原样往返 |
| 错误信息 | 英文（`TOML Parse error: Missing value after '='`），需要包装 |

## 最终决定

- **删除手写 parser**，改用 `Bun.TOML.parse/stringify`
- 保留 `src/core/toml.ts` 作为**薄封装**，只做两件事：
  1. 把英文错误信息包装成 `KanbanError`（退出码 2 + 中文可操作提示）
  2. `stringifyTomlWithHeader` —— 手动在文件头加中文注释块（Bun 的 stringify 不支持注释，
     而配置文件是给人读的，开头说明能省掉大量提问）
- 不用 `import config from "./config.toml"`：那是**编译期**导入并会被缓存，
  而配置文件是运行时生成/修改的（`agent-kanban remote set` 要能改它），必须运行时 `readFileSync` + `parse`

## 教训

在写"因为怕装不上依赖所以自己实现"的基础设施之前，先确认一下**运行时是否已经内置了它**。
手写解析器不只是多花时间，还引入了不完整的子集（用户某天写了个多行字符串就炸了），
而内置实现是完整规范 + 有人维护。

类似地，第一次写代码时的直觉（"agent 环境常常无法联网装依赖"）本身是对的，
但它只推翻了"引三方库"，没有推翻"用运行时内置能力"——这两者要分开判断。
