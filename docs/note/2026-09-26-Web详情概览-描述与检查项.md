# Web 详情抽屉补上描述与检查项（2026-09-26）

任务：T-0038（Web 侧）、T-0065（CLI 侧，同一批发现）

## 现象

用户在 Web 看板点开任务，看不到描述（description）与检查项（checklist）明细，
"新建任务时填了、创建完就没了"。

查下来是**两个独立缺陷**，叠加成同一个症状。

## 缺陷 1：描述压根没存进去（数据丢失）

`web/src/components/board.tsx` 里 `task.create` 的 params 写的是：

```ts
params: { title: input.title, body: input.body, /* ... */ }
```

而服务端 `CreateTaskParams`（`src/core/ops.ts`）读的是 `p.description`：

```ts
body: p.description ?? null,
```

多出来的 `body` 被**静默忽略**——没有报错、没有警告，前端 `executeOp` 拿到 `ok: true`，
用户以为存上了。数据库 `tasks.body` 列是对的，只是 Op 层把 `body` 翻译成了 `description`。

修法：`NewTaskDialog` 的回调字段也一起改名（`body` → `description`），
让"对话框字段名 = Op 参数名"，少一次心算。

### 为什么静态类型没拦住

`web/src` 不在根 `tsc --noEmit` 的范围里，前端的 `op: { kind: string; params?: Record<string, unknown> }`
本来就是弱类型。`test/web-contract.test.ts` 里已有一个 describe 在做前端源码的静态守卫
（"前端源码不得再拆 `{ task }` 包装"），这次把参数名也钉进去：

- 扫 `web/src/**` 里所有 `kind: "task.create"` 后面的 600 字符，要求含 `description:`、不含 `body:`；
- 顺带断言 `ops.ts` 里确实声明了 `description?: string | null`——改契约时会一起提醒改前端。

另外加了一条运行时测试把这个坑写死：传 `body` **不报错，但也存不进去**
（`expect(res.data.body ?? null).toBeNull()`）。静默失败没有回归测试，就一定会复发。

## 缺陷 2：详情抽屉压根没渲染这些字段

服务端 `task.get` 一直返回 `body`、`checklist`（逐项，含 `done_at`/`by`）、
`dependencies`、`unfinished_dependencies`。而 `TaskDetailSheet` 只画了
block_reason / 时间线 / 交接 / 计划——**概览数据一次都没被读过**。

卡片上唯一的线索是"还剩 N 项"，而且被包在 `task.progress > 0` 里：
新建的卡 `progress=0`，那一行也不显示。于是"描述和检查项"在新卡上等于完全不存在。

修法：

- `web/src/lib/api.ts`：新增 `TaskDetail`（`description` / `checklist` / `dependencies` /
  `unfinishedDependencies`），并做**归一化**——库里 checklist 是 TEXT（JSON），老数据可能是
  `null`、空串或手改坏的形状，详情面板不该因为一行坏数据打不开。
- `web/src/components/task-detail.tsx`：新增 `Overview` 小节，放在页签**上方**。
  放上方而不是再开一个页签，是因为"这活儿要做什么、还剩什么"正是打开卡片就想看的东西，
  藏进页签等于没显示。
  - 描述：`whitespace-pre-wrap` 当纯文本展示（用户数据，不引 markdown 渲染器）
  - 检查项：逐项列出，勾过的划线 + 显示 `by · 相对时间`（"谁勾的"是协作里最常被问的问题）
  - 关联任务：父任务 / 依赖，编号 + 标题，依赖未完成的标"未完成"（颜色跟 todo 令牌），
    查到且允许跳转时做成按钮，点击直接切到那张卡的详情
- `web/src/components/task-card.tsx`：`还剩 N 项` 从 `progress > 0` 里拆出来独立渲染

## 顺带发现的形状坑：`dependencies` 不是 id 数组

写运行时测试时才发现 `task.get` 的 `dependencies` 是 **TaskDep 对象数组**：

```
[{ taskId: "T-0006", dependsOnId: "T-0005", createdAt: 1767225600000 }]
```

而 `unfinished_dependencies` 才是 id 数组。第一版 `normalizeIds` 按"数组里都是字符串"过滤，
结果一个依赖都留不下（浏览器回归里之所以还能看到依赖行，纯属它兜底读到了
`unfinished_dependencies`）。改成两种形状都接，测试也把这条钉住。

同理 `checklist` **同名不同形**：`task.get` 给逐项数组，`taskToJson`（看板快照）给
`{total, done}` 计数。`normalizeChecklist` 遇到非数组直接返回空数组。

## 踩到的一个流程坑

改完 `web/src` 直接跑 `verify:web:ui` 会**假绿**：serve 读的是磁盘上的 `web/dist`，
不重新构建就还是旧产物。头一轮跑出来"描述/检查项"两条断言通过，其实是**时间线里的事件文案**
`检查项更新（1/2 完成）` 命中了 `sheet.text.includes("检查项")`——典型的假阳性。
`bun run web:build` 之后才看到真正的失败。

已写进 `AGENTS.md`：**改了 `web/src` 记得先 `bun run web:build`**。

# 附：CLI 侧的三处同类 bug（T-0065）

问了一句"那 CLI 能正常拿到吗"，实测发现**同一类"字段名读错"在 CLI 侧也有一份**。
MCP 那条路是好的（`kanban_task_get` 原样返回 `task.get` 的 data，模型自己看 JSON）。

## `kanban task show` 的三个问题

```
$ kanban task show T-0003
T-0003  [待办]  有描述有检查项的卡
  检查项
    ⬜ 步骤1
    ⬜ 步骤2
  依赖
    · undefined          ← ①
  可用操作：             ← ② 空的
                          ← ③ 描述整个不见了（必须加 --body）
```

**① 依赖打印 `undefined`**：`task show` 与 `task dep list` 都写成了
`Array<{ depends_on_id: string }>`，而 `getDependencies` 返回的 `TaskDep`
字段是 **`dependsOnId`**。`undefined` 被原样打印出来。

**② "可用操作"永远为空**：`executeWithHints` 返回 `{ data, nextActions }`，
`nextActions` 在 `data` **之外**。`taskShow` 只解构了 `data` 却去读 `task.next_actions`——
这个键压根不存在。旁边的 `claim` / `add` / `progress` 都显式写了
`out.data({ ...task, next_actions: nextActions })`，只有 show 漏了。

**③ 描述必须 `--body`**：与 Web 详情抽屉不一致。已改成**默认全文显示**，
`--body` 降级为**兼容参数**（传了不报错、不改变行为）——不然老脚本里写了它会直接 usage error。

## 顺带：`--timeline` 里露出原始事件名

`src/commands/task.ts` 有一份 `describeEventJson()` 的**重复实现**，比
`src/core/events.ts` 里的 `describeEvent()` 落后：缺 `dep_added` / `dep_removed` /
`plan_created` / `handoff_*` / `session_*`，于是时间线里直接打出 `dep_added`。
已删掉副本，改用 core 的那份——同一件事只该有一份实现。

## 根因与修法：把形状收敛到一个字段

`task.get` 的依赖有三个同名字段、形状各不相同：

| 字段 | 形状 |
| --- | --- |
| `dependencies` | `[{ taskId, dependsOnId, createdAt }]` |
| `unfinished_dependencies` | `["T-0003"]` |
| `dependency_details` | `[{ id, title, status, done }]` ← **新增，界面用这个** |

前两个都是"给机器看的"，各自去猜字段名就会各错各的（Web 猜错过一次，CLI 又错一次）。
所以服务端直接给出带标题与完成状态的那份，CLI 与 Web 共用。Web 保留了对
`dependency_details` 缺失的回退（老服务端 + 新前端的组合仍然能用）。

## 新增 `test/cli-output.test.ts`（11 条）

前面所有测试走的都是 Op 或 core 纯函数，证明不了"命令行把字段读错"这类**渲染层** bug。
这个文件真的 `Bun.spawn` 一次 `bun run src/cli.ts`，然后断言 stdout：

- 描述默认出现、换行保留
- 检查项逐项出现
- 依赖行是 `T-0001 上游（未完成）`
- 「可用操作」里有 `task claim T-0002`
- **输出里没有 `undefined`**（一次兜住整类 bug）
- `--body` 仍被接受
- 时间线里是 `新增依赖 T-0001` 而不是 `dep_added`
- `--json` 带 `next_actions` / `body` / `checklist` / `dependency_details`

写这个测试时踩到的坑：**`style.*` 不管 stdout 是不是 TTY 都上色**，所以 id 与标题之间
夹着 `\x1b[0m`，正则 `/T-0001\s+上游/` 匹配不上。测试里加了个 `strip()` 去 ANSI。

## 一个 git 层面的坑

`bun run web:build` 会重写 `src/server/assets.generated.ts`（内嵌资源清单），
而它**必须**保持 HEAD 里的空表占位形态。恢复要用

```bash
git restore --source=HEAD --staged --worktree src/server/assets.generated.ts
```

`git checkout -- <file>` 只从 index 恢复——如果 index 里已经存着构建产物，它会**静默无效**，
然后 `bun test` 报一堆 `Cannot find module '../../web/dist/assets/index-XXXX.js'`
（看起来像测试坏了，其实是清单被换掉了）。
