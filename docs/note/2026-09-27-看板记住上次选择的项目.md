# 看板记住最后选择的项目（2026-09-27）

需求：web 页面要记住最后选择的项目，没有选择（或记住的那个已经选不了了）就自动选第一个。

结果：**这个功能之前只做了一半**——`localStorage["kanban.project"]` 早就存了，
`getLastProject()` 也在用，但下拉框改选时只改了 React state，从来没往回写过。
页面上切换项目一切正常，刷新一下就弹回上一个。所以本次不是"加功能"，是**把断掉的那一半接上**，
再补一个之前没人管的失败分支。

## 改了什么

| 文件 | 动作 |
| --- | --- |
| `web/src/lib/project.ts` | **新增**：`resolveProject(remembered, accessible)`——纯函数，不引 React、不碰 localStorage，所以能脱离浏览器单测 |
| `web/src/lib/api.ts` | 新增 `clearLastProject()`（登录时 project 留空要清记忆） |
| `web/src/components/board.tsx` | `selectProject` / `clearProject` 两个出口；下拉框与登录表单改走它们；拉列表的 effect 只依赖 `token`；用 `resolveProject` 定项目并把自动选中的写回记忆；`fetchContext` 加空 project 守卫 |
| `test/web-project.test.ts` | **新增**：`resolveProject` 的五条分支 |
| `test/web-contract.test.ts` | 静态守卫：`onValueChange` 必须是 `selectProject`；每个 `setProject(` 都要配一次落盘 |
| `scripts/verify-web-ui.ts` | 浏览器回归「项目记忆」一节：多造一个 project，改 localStorage 再 reload，验证记住/兜底/写回 |

## 两个 bug，一句话各一个

### 1. 写了 state 没写 localStorage → 刷新就丢

```tsx
// 改之前
<Select value={project ?? undefined} onValueChange={setProject}>
```

`onValueChange` 直接接 setter。于是「记住」这件事只在下拉框**关掉之前**成立。
最难查的地方在于：它没有任何症状——切换生效、看板跟着换、连刷新前的一秒都是对的。

修法是让「改选」只有一个出口，且**读写不对称地分工**：

- 写：`selectProject` 同时写 state 和 localStorage（`clearProject` 对应清空）；
- 读：只从 `getLastProject()` 读。

这样"内存里的值"和"下次打开的值"不可能分叉，也就不需要在两处各写一遍同步逻辑。
登录表单那一栏是唯一需要 `clearProject` 的地方：它写的是"留空则自动选第一个有权限的"，
不把旧记忆清掉的话，换个 token 登录时会被上一个 token 留下的 project 截胡。

### 2. 兜底只判了「有没有选过」，没判「记住的那个还能不能访问」

```tsx
// 改之前
if (!project && list.length > 0) setProject(list[0]!.key)
```

`project` 非空就不动。于是 project 被删掉、或者用户换了个只授权了别的 project 的
token 之后，localStorage 里的 key 还在，界面却拿着它去打 `/api/board`：
**没有错误提示（`.catch` 吞了），只是一片空白**。

修法是把判断抽成 `resolveProject`：先用可访问列表校验记忆，不在列表里（和从来没选过）
走同一条路——退第一个，并把这个选择也写回记忆，下次打开不必再判断一次。
一个 project 都没有时返回 `null`，由界面保留占位，不硬凑一个不存在的 key。

## 几个取舍

- **为什么不等列表回来再发请求**（那样能彻底消掉失效记忆带来的那个 400）：
  代价是每次冷启动都多一个 RTT 才能看到看板。现在的做法是**乐观加载**：
  拿着记忆里的 key 先打，400 被 `.catch` 吃掉，列表回来后立刻自愈。
  代价是控制台里会多一条浏览器记的 network error（JS 屏蔽不了），
  `verify:web:ui` 已把它记成基线并在注释里写明来由。
- **为什么 effect 的依赖从 `[token, project]` 收成 `[token]`**：
  以前每切一次项目就重拉一遍项目列表（毫无意义），而且那个闭包里读到的 `project`
  是**上一次**的值。改掉之后顺带加了 `cancelled` 标志，StrictMode 下双跑不会误 setState。
- **记忆是全局的一个键，不按 token 分桶**。取舍是：同一个浏览器里换 token 登录时，
  旧记忆在新 token 下也恰好可访问的话会被沿用。对"记住上次看的"这个需求来说这是想要的；
  真要按 token 分桶，登录表单留空那条路径就得先清干净，反而更容易绕。

## 验证

```
bun run typecheck          # 0
bun run web:typecheck      # 0
bun test                   # 171 pass（test/web-project.test.ts 5 条 + web-contract 2 条新守卫）
bun run web:build
bun run verify:web:ui      # 「项目记忆」9 条全过，整节 0 失败
```

真浏览器那节值得单说：它用**两个** project 才有意义——只有一个的话，
"记住了"和"每次都回第一个"表现完全一样，分不出来。做法是改 `localStorage` 再
`Page.reload`（不去点 Radix Select：它只在 pointerdown 上展开，模拟不好容易假绿），
断言顶栏 combobox 显示的名字、看板卡片数、以及记忆有没有被改写回合法值。
最后把现场切回有卡的 project，免得后面的双语断言踩在空看板上。
