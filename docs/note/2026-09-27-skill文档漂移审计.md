# skill 文档漂移审计（2026-09-27）

起因：例行检查 `skills/agent-kanban` 是否需要更新。结果发现 skill 里**最关键的两条事实与代码相反**，
而且没有任何守卫能拦住这种漂移。

## 结论先说

skill 描述的是 v0.1.6 及更早的世界。最近三个 commit 改的东西（身份分片、远程模式写身份文件）
**一次都没有同步到 skill**——因为没人会去改它。

## 三类问题

### 1. 事实反向（会把 agent 带沟里）

| skill 写的 | 实际 |
|---|---|
| 身份写在 `.kanban/session`（单文件，5 个文件共 12 处） | `.kanban/sessions/<identity-key>`；**推不出 key** 才退回旧单文件 |
| 远程模式下 `session start` 不写本地文件，每条命令要带 `--session`（5 处，含 remote.md 一整个专节） | **本地远程都写**（`c108caa`） |

第二条最坏的地方在 `troubleshooting.md` 的症状速查表：它把 `missing session id` 的首要原因指向
"远程模式"，而 v0.1.7 升级后真实的首要原因是"你还没跑 `session start`"。agent 照着排障会查错方向。

### 2. 缺失

- **身份分片机制本身一条没写**：key 解析顺序、`KANBAN_SESSION_KEY`、`session start` 打的
  `identity :` 行、`--no-write`、旧二进制与新分片共存。用户级副本里有人手补过 Qoder 一节，
  仓库副本没有——两份 skill 就此分叉（5 个文件全 DIFF）。
- **`install-protocol` 零提及**。README 把它列为三种接入方案之一，skill 却不提——而"发现有 `.kanban/`
  但新会话不知道要先读看板"正是 skill 最该发力的场景。
- frontmatter 触发词里没有 `missing session id`：agent 撞上这个报错时，提示里没有任何一个词能命中 skill。

### 3. 顺带挖出的真 bug（不在 skill 范围）

`src/core/protocol.ts` 的协议模板里有**两条照着执行必失败的命令**：

```bash
agent-kanban task check T-0007 --item "add migration test"   # ❌ unknown command: task check
agent-kanban task claim T-0007 --ttl 7200                    # ❌ cannot parse lease duration
```

第一条 CLI 里根本没有 `task check` 子命令（`src/commands/task.ts` 的 switch 没有 `case "check"`），
正确写法是 `task progress T-0007 --check "..."`——**skill 反而写对了，是协议模板错了**。
第二条 `--ttl` 收时长字符串（`2h` / `30m` / `short`），不收分钟数。

这两行会被 `install-protocol` 写进**每个装过协议的项目**的 AGENTS.md，本仓库 `AGENTS.md` 就中招了。
讽刺的是 `src/core/protocol.ts` 自己的注释（"协议写错的话，agent 会照着执行然后失败，比没有协议更糟"）
早就把这类风险写清楚了，只是没人为这两行加守卫。

## 为什么能静默漂移这么久

`verify:docs` 的 `DOCS` 数组只有 `README.md` / `README-zh.md` / `Develop.md` / `Develop-zh.md`，
`test/**` 里也没有一条断言扫 `skills/`。skill 文档是**唯一一份没有任何自动化覆盖的产品文档**。

## 遗留（这次没做，建议做）

`cli.ts` 的 `case` 分支。这一条能同时挡住上面第 3 类和未来的任何协议模板回归——
**命令名写错在文档里是最便宜的 bug，在 skill 里却是最贵的，因为每个 agent 都会照着跑一遍。**
