## 三个当时犹豫、后来定了的点

### 1. 词典放一个文件还是拆出去？

想过程序。放一个文件最大的好处是**同键相邻**——校对译文时能一眼看到
`"common.cancel"` 的中英两行，不用在两个文件之间跳。190 条还在人能扫完的范围内，
拆出去反而增加"改了中文忘了改英文"的概率。以后超过 500 条再按 `board.*` / `card.*` 拆。

### 2. `en` 词典的类型写法

一开始写的是 `satisfies Record<MessageKey, string>`，结果**多写的键不会被发现**
（`satisfies` 只检查已有键的类型，不检查是否穷尽）。必须写成
`const en: Record<MessageKey, string>` 才是穷尽检查。

这正是第一次 `bun run typecheck` 报 `board.empty.title does not exist in type Record<...>`
的原因——那次编辑误删了 zh 里的 `board.empty.title`，而 en 里它还在。
**旧代码用 `satisfies` 时这个错误会被静默吞掉。** 教训：穷尽性约束要用注解
（`: Record<K, V>`）而不是 `satisfies`（非穷尽检查）。

### 3. 英文"还剩 N 项"要不要两条键？

复数规则上英文和中文不一样，但结论不是"英文一条中文两条"这么单纯：
英文 "1 left" / "5 left" 词形相同 → 一条够用；中文必须区分"1 项"和"N 项" →
两条。所以 `card.checklistLeftOne` 只有中文在用，英文那一份仍得填
（`Record<MessageKey, string>` 是全键穷尽的），填成和 `card.checklistLeft`
一样的 `{n} left` 即可，代码里只在 `n === 1` 时走 One。

一开始想上 ICU 复数（`{n, plural, one {# item} other {# items}}`），
发现为了一个数字要引入完整的 plural 解析器，不值。见计划 §3.2。

`Page.captureScreenshot`）逐个打开界面元素截图确认：

            Reopen | Cancel task

切换回中文后：

```

```

**已打开的对话框会即时变中文**（截图里 reason dialog 从 "Mark blocked" 直接
变成"标记阻塞"，没有重挂载）——因为 locale 在 Provider 的 state 里，
所有 `t()` 都是同一个 `useMemo` 出来的闭包。这是不该出现的重渲染吗？不是：
一次语言切换重渲染整个看板是预期成本，用户只在主动切换时才付。

## 没做的两件事（有意）

1. **不引第三方 i18n 库。** 理由与代价分析见计划 §2。
2. **不翻译后端下发的中文串。** `/api/context` 的 `next_actions`

   （因为同一个响应里本来就有 `last_seen_at`）。

## 追加：管理页（/admin）

看板做完之后才想起来管理页还全是中文，于是补上（计划 §7）。

### 插值在模板字符串里被吃掉转义

```ts
// TS 源里写的
s.replace(/\{(\w+)\}/g, (w, n) => ...)
```

这段代码在 `src/server/admin-page.ts` 的**模板字符串**里。模板字符串先跑一遍转义：
`\{` → `{`、`\w` → `w`。浏览器里拿到的正则是 `/{(w+)}/g`——要求字面的字母 `w`，
一个占位符都替换不掉。

**表现是没有报错的**：`serverInfo` 显示 `{projects} 个 project · {tokens} 个 token`
而不是 `2 个 project · 1 个 token`。页面看起来"就是没更新"，很容易往别处找原因。
唯一抓住它的办法是**实际读那个元素的 textContent**——截图看得出，
DOM 断言更快。

同类第二个坑：注释里写 `` `\\w` ``（用反引号包起来），
反引号**直接终止了模板字符串** → `tsc` 报 `TS1127 Invalid character`。
这个至少会报错，比较好查。

修法是彻底不用正则：

```js
for (const [name, value] of Object.entries(params)) {
  if (value === undefined) continue;   // 缺参数时保留占位符原样
  s = s.split("{" + name + "}").join(String(value));
}
```

**教训：任何嵌在 TS 模板字符串里的代码，反斜杠和反引号都要当作"多了一层转义"来审。**
写完后扫一遍 `Select-String -Path src\server\admin-page.ts -Pattern '\\'`，
只应该剩下有意的 `\\"`（JS 字符串里的引号）和 `\\n`（换行）。

### 输入框在英文下被截断

原来 `input { min-width: 200px }`，英文 placeholder 更长
（`Name (e.g. CI, contractor team)`）在 200px 里显示成
`Name (e.g. CI, contractor team`——少了结尾。改成
`min-width: 0; flex: 1 1 200px`，同一行控件多的时候先压缩而不是溢出。

**翻译之前不会暴露的排版问题**：中文 placeholder 大多 10 个字以内，
英文常常长 1.5 倍。翻译一做完就要重新扫一遍所有定宽/单行截断的地方。

### 回归门禁里的语言钉死

`verify:web-ui.ts` 里有一批中文断言（`aria-label="卡片操作"`、页签「交接」）。
界面语言改成读 `navigator.language` 之后，**在英文系统上跑这个脚本第一步就挂**。
加了 `--lang=zh-CN --accept-lang=zh-CN` 把默认语言钉死，双语行为另起一节断言。

顺便发现一个设计断言（不是 bug）：看板上切到英文后打开 `/admin`，
管理页**也是**英文——两个页面共用 `localStorage["kanban.locale"]`，
同一个 origin 不该有两套语言状态。测试一开始把它写成了"管理页默认中文"，
是断言错了，不是实现错了。

### verify:deploy 的坑

`bun run web:build` 内部会接着跑 `gen:assets`，把 `src/server/assets.generated.ts`
从**空表占位**覆盖成真实清单（里面全是 `../../web/dist/...` 的字面量路径）。
于是 `verify:deploy` 报"manifest 是空表占位"失败。
`git checkout HEAD -- src/server/assets.generated.ts` 还原即可。
这条已写进 `verify-deploy.ts` 的既有注释，但很容易再踩。

## 后续可做

- 第三种语言：看板加 `LOCALES` 一项 + `HTML_LANG`/`LOCALE_NAME` + 一份同键词典；
  管理页加一份 `DICT.<lang>`。看板的类型会告诉你缺哪些键，管理页不会（见下）。
- **管理页的词典缺键不会报错**——它是纯对象字面量，没有类型层面的穷尽检查。
  看板那边靠 `Record<MessageKey, string>` 兜住，管理页这边只能靠人。
  可以给管理页也加一个"键对齐"断言（比较 `Object.keys(DICT.zh)` 与
  `Object.keys(DICT.en)`），补进 `verify-web-ui.ts`。
- 一条 lint 规则禁止 `web/src/**/*.tsx` 出现中文字面量（当前靠
  `rg '[\x{4e00}-\x{9fff}]' web/src` 人肉扫，见 Develop-zh.md 的约定）。
  需要先支持"注释豁免"，否则注释里的中文会误报。
