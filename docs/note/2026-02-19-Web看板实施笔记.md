# Web 看板实施笔记（2026-02-19）

> 主题：用 shadcn/ui + 中性灰阶（白底纯灰线条）做 agent-kanban 的 Web 看板。
> 结果：Vite + React 19 + Tailwind v4 + shadcn(radix) 独立前端工程，
> `bun run web:build` 产出 `web/dist`，由 `kanban serve` 托管。

## 一、主题：中性灰阶 + 彩色状态

令牌分两层，职责不重叠：

- **中性色**（背景/卡片/边框/文字/主色）：纯灰阶，`chroma` 一律为 0。
- **状态色**（`--status-*`）：保持语义彩色，**不中性化**。

后者是有意为之：看板有 7 个状态 × 亮暗两套 = 14 个色值，
一并灰阶化的话，“这条卡在做什么”就只能靠读文字和猜位置判断了。
而中性色纯净，恰好让彩色状态标签在界面里跳得最明显。

| 令牌 | 亮色 | 暗色 | 语义 |
| --- | --- | --- | --- |
| `--background` | `#FFFFFF` 纯白 | `#252525` 近黑 | 纸面 |
| `--card` | `#FFFFFF` | `#333333` | 卡片靠阴影与边框分层，不靠底色 |
| `--foreground` | `#252525` 近黑 | `#FAFAFA` | 正文 |
| `--muted` | `#F5F5F5` | `#444444` | 次要底色 |
| `--border` | `#E5E5E5` | `#444444` | 线条 |
| `--primary` | `#252525` 近黑按钮 | `#FAFAFA` 白按钮 | 主动作 |
| `--status-todo` | `#C98A3C` 赭石 | L=0.75 | 待办 |
| `--status-doing` | 墨绿 | L=0.70 | 进行中 |
| `--status-blocked` | `#A6403C` 酒红 | L=0.67 | 阻塞 |
| `--status-done` | 草绿 | L=0.70 | 完成 |
| `--status-review` | 黛紫 | L=0.70 | 待评审 |
| `--status-stale` | 琥珀 | L=0.74 | 会话失联告警 |

两个容易被忽略的决策：

- **`--primary` 刻意不是 `--status-doing`**。主色若也是墨绿，“主按钮”与“进行中”就混同了，
  按钮会失去“这不是状态”的属性。所以主按钮走近黑，动作靠状态色自己说话。
- **暗色的状态色要提明度加彩度**。低亮度下人眼对色相的感知被压缩，
  墨绿/酒红在近黑底上会直接隐掉；中性色则按标准灰阶重排，不做暖度补偿。

**实现要点**：

1. 每个状态**只定义一个颜色**，淡底/边框/文字由 CSS `color-mix()` 从它派生：
   ```css
   .status-chip {
     background-color: color-mix(in oklch, var(--chip-color) 12%, transparent);
     border-color: color-mix(in oklch, var(--chip-color) 30%, transparent);
     color: var(--chip-color);
   }
   ```
   换主题时只改 `:root` 里的令牌，组件代码一行不动。
2. 状态色通过 `@theme inline` 接入 Tailwind（`text-status-doing` / `bg-status-todo`），
   遵循 shadcn 的"用语义类、不写裸色值"原则。
3. 标题用衬线（`--font-heading`）、正文用无衬线，呼应纸面感；中文回退到
   `PingFang SC / Microsoft YaHei / Noto Sans CJK SC`。

## 二、功能范围

按"加写操作"实现，即看板不只是只读视图：

- **拖拽改状态**（@dnd-kit）：前端先按状态机预检，不合法的转移**当场提示原因**，
  不发注定失败的请求。例：拖到「进行中」会说"必须先认领"，拖到「阻塞」会说"需要填原因"。
- **卡片菜单**：认领 / 更新进度 / 提交评审 / 完成 / 写交接 / 阻塞 / 释放 / 重开 / 取消
- **对话框**：需要 reason 的操作（阻塞/取消/重开）强制填原因；进度、交接、新建任务是完整表单
- **详情抽屉**（Sheet 而非 Dialog）：时间线 / 交接 / 计划三个 Tab。
  用抽屉是为了**不遮挡看板**——看单卡时还要看得见全局。
- **右栏**：待接手交接、会话列表（含失联标记）、`next_actions` 建议
- **SSE 实时刷新**：收到事件防抖 400ms 后重拉 `/api/board`
- **project 切换** + 亮暗切换 + 连接状态徽章

## 三、顺带修掉的后端缺陷

### `/api/projects` 永远 401（前端 project 列表一直是坏的）

这个端点的用途就是"客户端刚拿到 token、还不知道有哪些 project 可看"，
但它被挡在 `targetProject` 非空的检查**之后**——而那个检查存在的理由是
"所有业务接口都要指定 project"。于是它永远走不到自己的实现。

**修法**：

1. 把 `/api/projects` 移到 project 参数检查**之前**；
2. 鉴权改用新的 `authenticateTokenOnly()`——只验 token 本身（吊销/过期/角色），
   **不**校验 project 权限（因为还不知道要访问哪个）。

> 顺带说明：直接给 `authenticate` 传空 project 是不行的，
> 项目级 token 会因为 `token.projects.includes("")` 为 false 而被判 forbidden。
> 所以必须显式提供"跳过 project 检查"这个语义，而不是靠空字符串走个巧合。

**验证**：`scripts/verify-web.ts` 新增 3 条断言覆盖（有权限 / 无 project 参数可用 / 无 token 被拒）。

### 进度条颜色写死 `bg-primary`

`Progress` 的 indicator 是 `bg-primary`，导致"进度 100% 的待评审卡"显示绿色，
读起来像"已完成"。改成 `bg-current`，由调用方注入状态色。

## 四、headless 截图的三个坑

`scripts/snapshot-web.ts` 用来生成文档配图，踩了三个坑：

### 1. SSE 长连接让 Chrome 的 virtual-time 永不结束

`--virtual-time-budget` 等的是"网络空闲"，而 `EventSource` 一直 pending，
于是 `--screenshot` 永不触发，脚本直接卡死（第一次跑了 10 分钟被强制中断）。

**解法**：加 `?static=1` 开关跳过 SSE 建立。这是合理的调试开关，不只是为截图。

### 2. headless Chrome 里 localStorage 不跨页面导航持久

原本的方案是"同源 seed 页写入 localStorage → 跳看板"。
实测：seed 页里 `setItem` + `getItem` 都正常，但**跳转后看板读到 null**。

**解法**：改用产品本身就有的 `?key=` 分享链接登录——同一个页面内写+读，完全正常。
所以截图方案反而催生了一个真实有用的功能。

### 3. 假 token 会让截图变成登录页

调试时用 `k_probe_xyz` 假 token，页面正确地显示登录页（401 后清空凭据）。
差点误判成"前端登录逻辑坏了"。现在 `snapshot-web.ts` 在截图前会先做一次
`/api/projects` 自检，token 无效直接退出并给出 CLI 交叉验证的提示。

## 五、验证

```bash
bun run web:build        # 构建前端
bun run verify:web       # 端到端：静态资源/SPA 回退/路径穿越/看板 API/写操作/鉴权/SSE/缓存头
bun run snapshot:web     # 生成 docs/note/images/*.png
bun test                 # 后端 97 pass（web:build 不影响）
```

`verify-web.ts` 覆盖的关键项：

- `/` 返回真实前端而非占位页（并校验 HTML 引用了构建产物）
- **路径穿越**：`%2e%2e%2f` 编码绕过 URL 规范化后仍不泄露源码
- `index.html` 用 `no-cache`、带哈希资源用 `immutable`（发版后不会拿到旧壳）
- 远程 CLI 改数据 → `/api/board` 能看到（验证前后端同一份数据）
- SSE 推送：CLI 写一条 note，页面侧连接能收到

## 六、命令速查

```bash
bun run web:dev        # Vite 开发服务器（/api 自动代理到 127.0.0.1:7788）
bun run web:build      # 构建到 web/dist
kanban serve           # 托管 web/dist；未构建时 / 显示带构建指引的占位页
```

URL 参数（均会立即被 `replaceState` 抹掉，不留在浏览器历史里）：

| 参数 | 作用 |
| --- | --- |
| `?key=k_xxx` | 一次性登录（分享链接） |
| `?project=xxx` | 指定初始 project |
| `?theme=dark` | 强制亮/暗 |
| `?static=1` | 不建立 SSE（截图/无实时需求） |

## 八、注意

- `src/components/ui/` 是 shadcn 生成的源码，**不要手改**：
  更新用 `bunx --bun shadcn@latest add <组件>`，会保留本地改动。
- 本项目**严格禁止 `innerHTML`**（见 `docs/plan/002-接口契约.md` §5）。
  token 存在 localStorage，XSS 能读到，所以这条约束对前端是硬性的。
- `web/dist` 已 gitignore；未构建时 `kanban serve` 的 `/` 会显示带构建命令的占位页，
  而不是 404。
