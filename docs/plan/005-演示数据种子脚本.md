## 1. 要解决的问题

项目介绍、README、发版说明都需要看板配图。现有两条路都不好用：

- `scripts/snapshot-web.ts`：自己临时造一份**中文**数据（8 张卡、无依赖图、
  时间戳全是 now），只为截登录页与看板首屏。
- `手工摆卡片**：每次摆出来的都不一样，而且绕过 core 直接改库的话，
  事件流与投影会对不上——截图里的看板经不起 `rebuild` 检验。

所以要一个**可重复、可指定目标库、事件流自洽**的种子脚本，并且内容全英文
（截图文档面向英文读者）。

## 2. 目标与非目标

**目标**

| 目标 | 验收方式 |
|---|---|
| 18 张卡、7 种状态全覆盖、5 个会话、14 条依赖 | 脚本结尾打印统计 |
| 每张卡有描述、checklist、labels、优先级、工时 | `task show` 逐张看 |
| 有崩溃恢复的完整故事（崩溃 → 回收 → 接手交接） | `context` 首屏就是这条交接 |
| 有计划版本链（同一张卡两版） | `plan list --task T-0006` |
| 时间线铺开两周，不是同一秒 | `board` 里 "x 天前 / x 小时前" |
| 全英文界面数据 | 脚本内置 CJK 自检：事件/卡/交接/计划里出现任何中文即失败退出 |
| `doctor` 干净、`rebuild` 可重放 | 见 §6 |
| 不污染真实看板 | 目标库非空即拒绝，除非 `--reset` |

**非目标**

- 不做 Web 前端的 E2E 截图自动化（`snapshot-web.ts` 已经干这件事）。
- 不追求"每个状态都有完美样本"，只追求每种状态至少有一张能拿出手的卡。
- 不做多 project 演示（一次演示一个 project 就够，多 project 留给 `verify-auth.ts`）。

## 4. 关键决策

### 4.1 走 core API，不 spawn CLI

`spawn bun run src/cli.ts ...` 每次 200ms 且**无法注入时间**，所有时间戳都是 now，
看板会像"十八张卡同一秒创建"。直接调 `createTask` / `claimTask` / `transition` /
`updateProgress` / `writeHandoff` / `savePlan`，通过 `Actor.now` 注入逻辑时钟，
才能把时间线铺成两周。副作用是失去 CLI 的参数校验——但 `runTaskCommand` 内部
仍然跑完整的状态机与守卫，非法流转照样会抛错。

### 4.2 依赖写进 `createTask` 的 `blockedBy`，不是事后 `dep add`

事后补依赖会让所有 `dep_added` 事件挤在同一个时间点，与建卡时间差两周，
时间线一眼假。`createTask` 支持建卡时带依赖，代价是**建卡顺序必须让依赖在前面**
（脚本里 `dependsOn` 的目标都是更早创建的卡）。

### 4.3 全英文 vs core 里的两处硬编码中文

> ⚠ **本节已过时（2026-09-26 CLI 文案英文化之后）**。这两处硬编码中文已经不存在了：
> core 改写 checklist 进度时写入的是 `checklist updated (2/4 done)`，
> 崩溃自动合成交接也是英文（见 `docs/plan/006-CLI文案英文化.md`）。
> 所以 `scripts/seed-demo.ts` 里那条 `UPDATE events ... replace` 现在是**空操作**——
> 留着无害（replace 匹配不到就是原样返回），但不要再把它当成“core 会漏中文”的证据。
> 下面保留原文，是为了记录当初为什么要写这条 replace。

core 原来有两处会往**数据**里写中文，英文看板会当场破功：

1. `updateProgress` 勾选 checklist 后自动追加的 `task_note`：
   `"检查项更新（2/4 完成）"`。Web 时间线直接渲染 `data.text`。
   → 灌完数据后跑一条 `UPDATE events SET data = replace(...)` 把它换成
   `Checklist updated (2/4 done)`。只改事件里的展示文本，投影一个字段没动，
   所以 `rebuild` 重放结果不变。
2. `synthesizeCrashHandoff` 合成的崩溃交接（"原持有者 … 失联"）。
   → 见 §4.4。

没有绕开勾选功能，因为**带勾选状态的 checklist 正是截图最想看到的东西**。

### 4.4 崩溃故事：复刻 `reapZombies` 的前两步，但不调用它

`reapZombies` 会在同一个事务里调用 `synthesizeCrashHandoff`，产物是中文的。
所以脚本里手工写了与它**逐字对齐**的 SQL 与事件（会话标 crashed、卡退回 todo、
进度与 checklist 保留），只是不生成那条自动交接；改由接手方 `claude-web` 写一条
`kind: "reclaim"` 的英文交接。语义上更贴近真实接手（系统合成的交接措辞很机械），
而且 `rebuild` 重放一致。

### 4.5 会话必须区分"在干活"与"已收工"

**任何 CLI / HTTP 命令开头都会回收心跳超时的会话。** 演示数据放半小时后再看一眼，
看板会自己变成"全部会话崩溃、所有卡被退回"，还会冒出一堆中文崩溃交接。
真实看板里这个问题不存在，因为干完活的 agent 都会显式 `session end`。
所以脚本照做：3 个活跃会话心跳新鲜，1 个 `closeSession` 收工（因此不出现在
`board` / `context` 的会话列表里），1 个显式崩溃。

另外把 `grace_ms` 默认拉到 30 分钟（`--grace` 可改）作为兜底——让数据放几天再截图
也长得一样。

### 4.6 给进行中的卡补一次续租

租约是"认领时间 + 15 分钟"，而剧情里的认领发生在几小时前，不补的话界面上会显示
"租约已过期"。真实运行时这由 agent 每隔几分钟的 `progress` / `note` 隐式完成
（`updateProgress` 顺手续租），所以脚本最后对每张 doing 的卡显式调一次
`renewLease`——语义一致，且续租按设计不写事件，时间线与 `rebuild` 都不受影响。

## 5. 安全性

- 目标库已有任务 → **拒绝执行**，并区分"上次灌过演示数据"（读 `meta.demo_seeded_at`）
  与"这是一个真库"两种提示。
- `--reset` 只删 `kanban.db` / `-wal` / `-shm` 三个文件，不碰 `config.toml`、
  `journal/`、`plans/`。
- 库不存在时等价于 `agent-kanban init`：建 schema、建 project、写初始配置；
  仅当数据目录真的是 `.kanban` 且没有配置文件时才补 `config.toml`。
- project key 默认由库所在目录名派生；复用已有库时沿用库里那个，避免同一份数据
  被挂到两个 project 下（那正是 `task_deps` 漏 project_key 的成因）。

## 6. 验证

```bash
bun run seed:demo --db $env:TEMP/kanban-demo-test/kanban.db --reset
bun run src/cli.ts --db $env:TEMP/kanban-demo-test/kanban.db doctor    # 无告警
bun run src/cli.ts --db $env:TEMP/kanban-demo-test/kanban.db rebuild   # 见下
bun run src/cli.ts --db $env:TEMP/kanban-demo-test/kanban.db board
bun run src/cli.ts --db $env:TEMP/kanban-demo-test/kanban.db context
```

`doctor` 输出干净（`demo_seeded` 库里连"4 小时无进展"都没有）。
`rebuild` 报 2 处漂移，**不是种子数据的问题**，是 core 的真 bug：
`transition` 进 `review` 时保留 `assignee_session_id`，而 `rebuild.ts` 的
`task_review` 分支把它置空 → 任何停在"待评审"的卡都会让 `rebuild` 报漂移。
纯 CLI 即可复现（`task add` → `claim` → `review` → `rebuild`），
详见 `docs/note/2026-09-26-演示数据种子实施笔记.md`。

## 7. 与 `scripts/seed-board.ts` 的区别

| | `seed-board.ts`（dogfood） | `seed-demo.ts`（本脚本） |
|---|---|---|
| 目的 | 把 M1-M6 真实开发过程记进看板 | 给文档截图造假数据 |
| 内容 | 真实里程碑 | 编的 v0.2 里程碑 |
| 幂等 | 按标题匹配，重复运行不重复建卡 | 目标库非空即拒绝（要 `--reset`） |
| 语言 | 中文 | 全英文 |
| 能否 `task claim` | 能（是真任务） | **不能**（是假数据） |
